缺失估价清单（16.9：未知单位价 0 / 未知升级倍率 1）
================================================================================
本文件落实静态审计 16.9：`UNIT_PRICES.get(unit, 0.0)`（constants/unit_prices.py）
与 `POWER_FACTORS.get(name, {})`（upgrades.py）对未知条目静默按 0 / 1 计。

- 未知单位当前按 0 计价：`Slot.price()` / `Card.price` 用
  `UNIT_PRICES.get(unit, 0.0)`，漏价单位不贡献战力，属于"低估"而非崩溃。
- 下表保留原始静态审计中的 **32 个缺 UNIT_PRICES 单位名**；第四节已补入其中 11 项、用户确认补入 17 项，当前仍有 4 项待定（按类别分组）。
- 「建议价格」栏留给用户填写（本文件不预设数值）；已由 JSON Price 唯一反推的 11 项及用户确认的 17 项
  见第四节说明并已写入价格表；「来源/备注」栏给出出处，供定价时参考同价值档位的既有单位。
- 填好后把数值写进 `src/star_tarven_simulator/constants/unit_prices.py` 即可生效。

五、缺 POWER_FACTORS 的升级 4 项（通常无需补）
════════════════════════════════════════════════════════════════════════
这些升级**没有持续战斗升级**（不改变攻/防/生存/功能倍率），缺倍率时
`POWER_FACTORS.get(name, {})` 缺省为空 dict -> prod = 1，等效战力按基础价值计，
**是正确的**；若给它们补倍率反而会把已计入的单位价值重复计价。除非实盘确认
有持续战斗成长，否则保持缺省：

#    升级名       类型             原因（为何缺省即正确）
----  ----------  ---------------  ----------------------------------------
 1    黄金矿工    经济事件          「卡牌变为金色，每回合开始获得1晶体矿」——
                                   矿物收益不折算战斗倍率（upgrades.json L2）
 2    修理无人机  即时增兵          一次性效果：+（酒馆等级+3）修理无人机，
                                   单位本身已按基础价值计价
 3    折跃援军    即时增兵          一次性效果：+2高阶圣堂武士 +3水晶塔，
                                   单位本身已计价（出售传播逻辑在 game.py）
 4    原始尖塔    即时增兵          一次性效果：+2原始异龙 +4精华，
                                   单位本身已计价

参考（upgrade-system.md）："一次性增兵不再额外套增兵倍率，避免与新增单位的
基础价值重复计价；经济效果（例如黄金矿工）也不直接伪装成战斗倍率。"

================================================================================
使用说明
================================================================================
1. 在「建议价格」栏填数值（与既有价格同一量纲：单位价/矿；未知参考档位见各备注）。
2. 把最终数值写入 src/star_tarven_simulator/constants/unit_prices.py（UTF-8）。
3. 若某单位确应计 0（如纯计数物/衍生挂件），建议在 unit_prices.py 显式写 0，
   使"缺项"与"明确为 0"在代码里可区分（当前 .get 缺省 0 无法区分二者）。
