# 卡牌描述格式（新版 v260822 vs 旧版）

> 新版数据：`data/v260822_card.json`（155 张卡）。本文说明字段结构、`<c val>` 颜色标记约定，
> 以及相对旧版（`ext/tarven_interface/data/card_gold/v250302*.json`）的格式优化点。

## 1. 新版单条卡牌结构

```json
{
    "name": "死神火车",
    "level": 1,
    "race": "terran",
    "uuid": 0,
    "price": 500.0,
    "units": { "收割者": 3, "恶火": 2, "反应堆": 1 },
    "description": [
        "<c val=\"008000\">任务：</c>让1张卡牌进场",
        "<c val=\"FFFF80\">奖励：</c>获得1晶体矿"
    ],
    "gold_description": [
        "<c val=\"008000\">任务：</c>让2张卡牌进场",
        "<c val=\"FFFF80\">奖励：</c>获得2晶体矿"
    ],
    "tags": ["terran"],
    "gold_tags": ["terran"]
}
```

字段：
- `name` / `race`（`terran|protoss|zerg|neutral`）/ `level`(int) / `uuid`(int) / `price`(float)。
- `units`: **dict** `{单位名: 数量}`。
- `description`: **字符串列表**，每个元素是一条独立能力子句（含 `<c val>` 标记）。
- `gold_description`: 金色（三连）版本描述，结构同上。
- `tags` / `gold_tags`: 显式标签列表（普通/金色）。`race` 会在加载时自动补进 tags。

## 2. `<c val="RRGGBB">关键词</c>` 颜色标记

新版把关键词/机制词用颜色包裹。**颜色 = 语义类别**，可据此确定性地识别触发时机与机制归类，
不必再靠脆弱的中文子串猜测。下表为实测统计（出现频次 + 典型内容）：

| 颜色       | 类别           | 典型关键词 |
|-----------|----------------|-----------|
| `FF0000`  | 唯一 / 单位限定 | `唯一：`、`生物`、`英雄`、`非英雄`、`摧毁`、`非虫族` |
| `FF8000`  | 人族挂件 / 集群 | `反应堆`、`挂件`、`科技挂件`、`集群(N)：` |
| `008080`  | 定点部署        | `定点部署` |
| `00FF00`  | 快速生产 / 升级 | `快速生产：`、`轨道空降`、`高级科技实验室`、`暗影战士` |
| `0080FF`  | 折跃            | `折跃` |
| `800040`  | 注卵            | `注卵`（另有变体 `7f003f`） |
| `A65353`  | 黑暗            | `黑暗值`、`黑暗容器` |
| `008000`  | 任务            | `任务`、`任务：` |
| `DEDE00`  | 集结            | `集结(N)：`、`集结` |
| `80FFFF`  | 神族能量        | `水晶塔`、`虚空水晶塔`、`能量强度` |
| `8080FF`  | 灵能            | `灵能`、`灵能：` |
| `804000`  | 辅助卡          | `辅助卡` |
| `800080`  | 孵化            | `孵化` |
| `8000FF`  | 原始虫群 / 供养 | `原始虫群`、`供养(N)：` |
| `FFFF80`  | 奖励            | `奖励：`（与“任务”配对） |
| `FF00FF`  | 夺取            | `夺取` |
| `8080C0`  | 虚空投影        | `虚空投影` |
| `FFFF00`  | 集结（高数值）  | `集结(13)：`、`(7)：` |
| `00FF40`  | 卡名 / 护盾     | 卡名引用、`护盾充能` |
| `00FFFF`  | 虚空水晶塔      | `虚空水晶塔` |

> 注意事项：
> - 同一语义可能有大小写/近似色变体（如 `FF0000` vs `ff0000`、`800040` vs `7f003f`）。
>   解析时颜色比较**忽略大小写**，并对近义色做归一化。
> - 颜色只是**分类信号**，具体数值（“获得 **2** 跳虫”）仍需从文本解析。
> - 一条子句可能含多个标记，如
>   `<c val="FF8000">集群(7)：</c><c val="FF00FF">夺取</c>场上所有1-2星卡牌`。
> - 有些标记是**被动 tag 声明**而非触发效果，如 `具有<c val="A65353">黑暗容器</c>`、
>   `能够<c val="008080">定点部署</c>` —— 这些对应 `tags`，不应生成 handler。

## 3. 任务/奖励的配对

任务类卡牌把“任务”与“奖励”拆成**两条相邻描述**：
```json
"description": [
  "<c val=\"008000\">任务：</c>让1张卡牌进场",
  "<c val=\"FFFF80\">奖励：</c>获得1晶体矿"
]
```
旧版是单行 `任务: 让1张卡牌进场 奖励: 获得1晶体矿`（parser 里靠合并相邻行来还原）。
新版天然分行，解析时应把“任务行 + 紧邻的奖励行”组合成一个 `TaskActionHandler`：
目标从任务行解析，奖励逻辑从奖励行解析。

## 4. 旧版格式（对照）

旧版 `v250302.json` 单卡：
```json
{
  "name": "死神火车", "level": "1", "id": 0, "race": "terran", "price": "500",
  "description": "任务: 让1张卡牌进场 奖励: 获得1晶体矿",
  "units": [ {"name":"收割者","count":"3"}, {"name":"恶火","count":"2"} ]
}
```

## 5. 新版做了哪些优化（重点）

| 维度        | 旧版 v250302                              | 新版 v260822                         |
|------------|-------------------------------------------|--------------------------------------|
| 描述结构    | 单个字符串，空格拼接多条能力                | **字符串列表**，一条能力一元素        |
| 关键词识别  | 纯中文子串匹配 + md5 兜底（脆弱、需去噪）    | **`<c val>` 颜色标记**，语义确定性分类 |
| 金色描述    | 放在单独文件（如 `*_gold.json`），需 diff   | 同卡内 `gold_description` 直接给出     |
| 金色标签    | 需从金色描述推导                            | 显式 `gold_tags`                      |
| tags        | 从描述里扫已知 tag 串抽取                    | 显式 `tags` 字段                      |
| units       | `[{name, count}]` 列表，值为字符串           | `{name: count}` dict，值为 int         |
| 类型        | `level`/`price`/`count` 均为字符串           | `level`(int)、`price`(float)、int 数量 |
| id          | `id`                                        | `uuid`                                |
| 无用尾注    | 混在描述里（寿仙杯冠军、社区说明等噪声）      | 已从结构化描述中清理                   |

对写代码的直接影响：
1. **不再需要 `parser.py` / `card2program.py` 那套“归一化 + 子串匹配 + md5”流程。**
   新版可按“逐行 + 颜色标记”做确定性解析。
2. **金色版本不再需要跨文件 diff**，`gold_description` 直接映射到 `gold_event_handlers`。
   （注意：旧 `Card.from_json` 从未填充 `gold_event_handlers`，是重写时要补的缺口。）
3. **units/tags 已是干净结构**，加载时无需类型转换与推导。
